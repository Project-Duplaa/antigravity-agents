# DESIGN BRIEF TEMPLATE — Mandatory Pre-Development Artifact

> Every new project MUST have a `.design-brief.md` file in its root directory.
> This file is generated by the `product` and `creative` agents BEFORE any design or development begins.
> The `designer`, `developer`, and `enhancer` agents MUST READ this file before producing any UI.

---

## WHEN TO CREATE THIS FILE

1. **New projects** (greenfield): `product` agent creates Section 1-3, `creative` agent fills Sections 4-8.
2. **Major features**: Create a feature-specific brief in `docs/briefs/FEATURE-NAME.design-brief.md`.
3. **Redesigns**: Audit-first, then create the brief with `[REDESIGN]` flag and preservation notes.

## ENFORCEMENT RULES

1. **No brief = No development.** If a `developer` agent receives a task without a design brief, it MUST request one from the `product`/`creative` agents before writing UI code.
2. **Brief is immutable during sprint.** Once approved, the design brief is locked for the current implementation cycle. Changes require a new brief version.
3. **Enhancer validates against brief.** The `enhancer` agent cross-references every visual decision against the design brief. Deviations without justification = FAIL.
4. **Brief lives in project root.** Always at `.design-brief.md` or `docs/briefs/[name].design-brief.md`.
